# Scholar Harness 商业飞轮设计

> 商业飞轮的核心不是“功能越多，用户越多”，而是：**开放标准降低采用门槛，可靠任务产生可复用科研资产，获授权的反馈提升质量，质量驱动个人付费和团队扩张，收入再投入核心能力与生态。**

## 1. 飞轮总图

```text
开放标准、轻量运行时与示例工作流
        ↓
更多开发者、科研人员与合作伙伴接入
        ↓
更多 Skill、插件、模板、数据连接器与学科方案
        ↓
更多个人用户通过论文/PDF/分析任务进入
        ↓
更多可追溯任务完成与可复用研究资产
        ↓
经授权的质量反馈、评估样本和失败模式
        ↓
检索、证据、执行和交付质量提升
        ↓
Pro 转化、Lab 扩张与 Enterprise 标准化
        ↓
收入投入执行内核、质量体系、生态激励与合规
        └──────────────────────────────→ 回到起点
```

飞轮每一步都必须有真实的价值交换：社区获得分发和收益，用户获得更可靠的任务结果，机构获得治理和复用，SH 获得订阅收入与合法质量反馈。

## 2. 两个相互咬合的子飞轮

### 2.1 产品质量飞轮

```text
用户发起真实科研任务
→ 执行内核记录计划、工具、证据、产物和人工修订
→ 评估系统识别成功、失败与返工原因
→ 优化上下文、检索、工具路由和质量门禁
→ 更高成功率、更低成本、更强信任
→ 用户执行更多高价值任务
```

这里沉淀的是结构化任务遥测和经授权反馈，不是默认收集用户原始论文与数据。

### 2.2 生态与商业飞轮

```text
开放 SDK / schema / 轻量运行时
→ 第三方贡献连接器、Skill、模板
→ 适配更多学科、工具和机构环境
→ 降低获客与交付成本
→ 更多 Pro / Lab / Enterprise 用户
→ 市场分成、认证和服务机会
→ 更多高质量维护者加入
```

生态数量不是目标，稳定、可验证和有人维护的扩展才是目标。

## 3. 每一层的价值交换

| 参与者 | 获得什么 | 贡献什么 |
|---|---|---|
| 个人研究者 | 更快完成可信任务、跨项目复用资产、模型自由 | 订阅、经授权反馈、模板改进 |
| 实验室 | 共享知识、标准流程、权限和审计 | Lab 订阅、领域流程、团队采用 |
| 开发者/维护者 | 分发、声誉、测试工具和市场收入 | Skill、插件、连接器、修复 |
| 数据/工具伙伴 | 新用户、标准接口、联合方案 | 合规 API、连接器、服务能力 |
| 高校/企业 | 私有部署、治理、合规和服务保障 | 年度合同、标准化需求、行业背书 |
| SH | 收入、生态、评估反馈和标准影响力 | 核心内核、质量、安全、运营与分发 |

## 4. 网络效应如何真正成立

### 4.1 兼容性网络

统一 Skill/MCP/连接器契约后，一个扩展能服务更多用户，一个用户增长也提高维护者收益。

### 4.2 信誉网络

为扩展提供签名、测试、权限、维护状态、成功率和用户评价。高信誉扩展降低选择风险，形成可积累的作者品牌。

### 4.3 工作流复用网络

公开模板可被复用和改进；机构模板在权限范围内复用。每次改进都降低下一次任务成本。

### 4.4 组织资产网络

课题组的文献、证据、数据字典、分析方案、图表标准和投稿规则连接成私有 Research Asset Graph。团队使用越深，资产价值越高，但必须支持完整导出，不能靠数据绑架。

### 4.5 标准网络

如果 SH 的资产 schema、能力清单和评估协议被更多工具采用，SH 将从应用变成科研 Agent 的兼容层。

## 5. 市场与生态机制

### 5.1 扩展分类

- 免费开源：基础连接器、公共数据库、通用模板；
- 免费认证：通过兼容性与安全检查的社区扩展；
- 付费扩展：专业数据库、学科流程、机构模板；
- 官方扩展：影响核心质量、合规或商业交付的能力。

### 5.2 上架门禁

- 明确许可证、作者和源码/二进制来源；
- 声明权限、网络域名、文件范围和外部命令；
- 通过结构、安装、卸载、恢复和安全测试；
- 提供输入输出 schema、失败行为和维护承诺；
- 高风险扩展必须人工审核和隔离运行。

### 5.3 建议分成

早期可给予维护者 80%–90% 的净收入以吸引供给；生态成熟后可根据分发、托管、结算和企业支持调整。不要在供应不足时以高抽成阻碍生态。

## 6. 从 10 万到 100 万用户的增长结构

### 0–10 万：单点口碑

- 入口：证据写作、PDF Wiki、Meta/数据分析；
- 渠道：高校社群、实验室、课程、开源社区、内容示范；
- 目标：证明灯塔工作流成功率和 Pro 付费意愿；
- 关键：本地优先、自带 Key 和合理默认值降低服务成本。

### 10–30 万：生态分发

- 推出公开 SDK、注册表和维护者计划；
- 与 Zotero、Office、R/Python、数据平台形成联合入口；
- 建立学科模板和认证服务商；
- Pro 形成稳定个人收入，Lab 开始成为扩张引擎。

### 30–100 万：组织与标准

- Lab 空间成为团队协作和资产复用入口；
- Enterprise 提供身份、治理、私有部署和 SLA；
- 区域伙伴和行业解决方案通过标准扩展交付；
- 公共 schema 和兼容性认证形成事实标准。

## 7. 收入飞轮

```text
Free 获客与生态采用
→ Pro 为个人生产力、可信证据和高级任务付费
→ 同一用户带入课题组
→ Lab 为共享资产、协作、治理和配额付费
→ 成熟课题组推动高校/企业采购
→ Enterprise 为私有部署、集成、审计和 SLA 付费
→ 官方与第三方市场扩大 ARPU 与场景覆盖
```

收入结构应逐步从纯个人订阅变成：个人订阅 + Lab 年费 + Enterprise 合同 + 市场分成 + 标准化服务。

## 8. 核心指标树

### 北极星指标

**每周被用户接受、具备来源与产物的科研任务完成数。**

### 获客

- 新用户首个任务完成率；
- 首次价值时间；
- 模板/扩展带来的自然新增；
- 邀请进入 Lab 的比例。

### 激活与留存

- 7/30/90 日项目留存；
- 每用户完成任务数；
- 研究资产复用率；
- 跨工作流使用比例。

### 质量

- 引用可验证率；
- 任务成功与恢复成功率；
- 用户接受/修改/拒绝率；
- 每个完成任务的人工返工时间。

### 商业

- Free→Pro、Pro→Lab 转化；
- Lab 席位扩张和净收入留存；
- 每任务模型与支持成本；
- 企业交付中标准产品收入占比。

### 生态

- 通过验证的活跃扩展；
- 90 日仍维护的扩展比例；
- 扩展驱动的任务完成量；
- 维护者收入与复购。

## 9. 飞轮的反作用与控制

| 反作用 | 后果 | 控制方式 |
|---|---|---|
| 功能无限增加 | 可靠性下降、定位模糊 | 灯塔工作流与路线门禁 |
| 低质量插件泛滥 | 信任和安全受损 | 权限、测试、签名、评级、下架机制 |
| Prompt 和上下文膨胀 | 成本高、响应慢、结果漂移 | 动态清单、按需调用、缓存与预算 |
| 机构定制不可复用 | 毛利下降、团队被项目绑架 | 配置化、插件化、产品评审 |
| 用户数据成为隐性训练料 | 法律与信任风险 | 明示授权、最小化采集、可删除与可导出 |
| 无限套餐/低价竞争 | 服务不可持续 | 能力分层、计算成本透明、自带 Key |

## 10. 分阶段启动飞轮

### 未来 90 天

- 定义北极星指标和灯塔工作流评估；
- 完成 Free/Pro 权限而非字符包的产品化；
- 建立 20 个官方认证扩展的种子集合；
- 招募 5–10 个实验室设计 Lab；
- 发布用户数据、扩展权限和许可证政策。

### 3–9 个月

- 上线资产图谱最小版本和跨任务复用；
- 上线扩展注册表、签名、测试与维护状态；
- 推出 Lab 试点和标准 onboarding；
- 建立质量评估看板与成本看板。

### 9–18 个月

- 推出市场分成；
- 与科研软件和数据伙伴联合分发；
- 标准化 Enterprise 部署包和控制面；
- 发布公共兼容性基准与认证。

## 11. 最终原则

SH 应追求的是基于开放兼容性的正向网络效应，而不是封闭格式造成的迁移成本：

- 用户资产始终可导出；
- 模型和工具可替换；
- 生态标准尽量开放；
- 质量、治理和可靠执行形成付费价值；
- 商业收入继续强化公共标准与核心内核。

只有当“更多使用”能稳定带来“更高质量、更多复用和更低交付成本”，商业飞轮才真正成立。
