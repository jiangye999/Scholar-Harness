# Scholar Harness 产品边界分析

> 战略结论：Scholar Harness（下称 SH）当前最准确的产品定义是 **“本地优先、证据驱动、可扩展的科研 Agent 工作台”**。它以论文和科研项目为切入口，把文献、证据、数据、分析、写作和交付串成可恢复、可审计的任务。它不是一个通用聊天壳，也不应在现阶段对外宣称已经是完整的“科研 AI 操作系统”。

## 1. 审计依据与现状判断

本判断来自当前仓库的实际实现，而非产品愿景推演。已核实的主链路包括：

- Electron 桌面壳、本地 Express 服务、云端账号与授权服务；
- 两级 Agent、统一聊天执行内核、阶段恢复、进度日志和文件产物；
- Embedding 文献库，以及 BM25 粗筛 → 候选向量检索 → reranker 的级联检索；
- PDF Wiki 句子级证据库，以及 `sentenceId`、文中引用、尾注、证据句和参考文献映射；
- Auto Research、文献计量、Meta 分析、数据分析和 R 作图；
- Skill、MCP 插件、插件市场与构造 Agent；
- 订阅、授权码、分销、用量和官网交付。

因此，SH 已经超出“AI 写论文”范畴，但各能力的成熟度不同。当前真正连贯的主线是：

```text
科研任务
  → 项目资料与文献进入本地工作区
  → Agent 规划并调用检索/分析/写作工具
  → 证据与结论建立可追溯关系
  → 形成可继续修改的文稿、图表、数据和审计记录
```

## 2. SH 到底是什么

### 2.1 用户角度

用户不应该被要求理解 Agent、RAG、MCP 或工作流引擎。对用户而言，SH 是：

> **一个能读懂其科研项目、调用本地资料和专业工具，并把复杂科研任务持续做完的 AI 研究工作台。**

不同用户看到的入口可以不同，但产品身份必须统一：

| 用户 | 首要认知 | SH 帮其完成的结果 |
|---|---|---|
| 研究生/个人研究者 | 会引用、会分析、会修改文件的科研助理 | 从资料到可信草稿、图表与投稿材料 |
| PI/实验室负责人 | 团队科研资产与流程工作台 | 复用实验室证据、规范和方法，降低带教与返工成本 |
| 高校/研究机构 | 可治理、可私有部署的科研 Agent 平台 | 在权限、审计和数据边界内规模化部署科研 AI |
| 开发者/生态伙伴 | 科研 Skill 与插件运行平台 | 构建、分发和商业化科研能力包 |

“AI 论文助手”适合作为获客语言和首个高频场景，不适合作为公司长期边界；“科研知识管理”是底层能力，不是完整结果；“科研 Agent 平台”最接近当前产品；“科研 AI 操作系统”是未来愿景。

### 2.2 技术角度

SH 实际是六类技术系统的组合：

1. **科研任务执行内核**：意图、任务、工具调用、状态恢复、日志、产物与错误降级。
2. **科研 Agent 编排层**：规划 Agent、执行 Agent、检索 Agent、质量检查和专用工作流。
3. **研究资产层**：项目、长期记忆、文献、PDF、句子级证据、数据集、分析结果和草稿。
4. **混合检索与证据层**：结构化解析、BM25 候选召回、向量检索、重排、来源追踪和引用校验。
5. **工具与生态层**：Skill、MCP、R/Python/Office、插件市场、构造 Agent。
6. **治理与商业层**：身份、订阅、额度、分销、更新、团队权限和未来的组织级审计。

这意味着 SH 的技术竞争对象不是单独的聊天产品，而是“模型 + 研究数据 + 专业工具 + 工作流 + 交付环境”的组合方案。

### 2.3 商业角度

SH 不应出售“生成字数”，而应出售三类可量化结果：

- **任务完成度**：从一个研究目标到可交付成果的完成率和时间；
- **证据可信度**：结论、句子、引用和原始来源之间的可追溯性；
- **科研资产复用度**：个人或团队积累的文献、证据、分析模板、规范和工作流能否重复使用。

商业上应形成四层价值：个人效率工具、个人研究资产库、实验室协作与治理平台、机构级私有科研 Agent 基础设施。

## 3. 产品边界

### 3.1 必须属于 SH 的核心

- 项目化科研上下文，而非无状态聊天；
- 文献、PDF、数据、图表、文稿之间的统一资产模型；
- 证据来源、引用关系、处理过程和产物的可追溯性；
- 长任务可恢复、可取消、可续跑、可审计；
- 模型无关和工具可扩展，允许 BYOK、本地模型与云模型组合；
- 从研究问题到分析和写作交付的跨工具工作流；
- 用户对本地数据、导出和删除的控制权。

### 3.2 可以由生态承担的能力

- 学科专用 Skill、期刊模板和检查规则；
- 外部数据库、仪器、统计软件和知识库连接器；
- 非核心的图表风格、文档模板、可视化主题；
- 长尾科研工作流和机构内部模板；
- 通用模型能力和基础 OCR/PDF 解析组件。

### 3.3 明确不做或不自建的能力

- 不训练通用基础大模型，不与模型厂商比参数；
- 不做通用办公套件、通用浏览器或 Notion 全功能替代品；
- 不做没有证据约束的“论文代写平台”；
- 不建设封闭文献格式或阻碍用户导出的数据孤岛；
- 不以绕过验证码、登录或出版商条款的自动化作为产品能力；
- 不把每个研究方法都内置成核心代码，长尾能力由插件和 Skill 承担；
- 不在主产品成熟前扩张到教学、行政、招聘等泛高校场景。

## 4. 建议的产品层级

```text
对外品牌层：科研 Agent 工作台
  ├─ 获客切入口：论文写作、PDF 阅读、文献证据核验
  ├─ 专业工作流：Auto Research、计量、Meta、数据分析、R 作图
  ├─ 资产底座：Research Asset Graph（研究资产图谱）
  ├─ 执行底座：Research Execution Kernel（科研任务执行内核）
  └─ 生态接口：Skill / MCP / API / 模板市场
```

其中，“研究资产图谱”不只是网状图 UI，而是项目中的文献、证据句、主张、数据、分析、图表、草稿与来源之间的结构化关系。“执行内核”不只是 Agent 循环，而是包含恢复、权限、日志、产物、成本和质量门禁的可靠运行层。

## 5. 北极星与产品原则

### 北极星指标

建议采用：

> **每周完成并被用户接受的“可追溯科研交付任务”数量。**

任务必须同时满足：有明确目标、有实际产物、有来源/操作记录、用户接受或继续使用。仅统计消息量、Token 数、生成字数或打开次数会鼓励错误增长。

### 产品原则

1. **证据优先于语言流畅**：不能用漂亮文本掩盖证据不足。
2. **项目优先于会话**：会话是交互界面，项目资产才是长期载体。
3. **执行优先于建议**：在权限允许时，完成文件、分析和检查，而非只给教程。
4. **可恢复优先于一次成功**：科研长任务必须能断点续跑。
5. **开放接口、保护智能内核**：让生态扩张，同时保护决定质量和转化的核心。
6. **用户拥有数据**：数据可导出、可删除、可迁移，平台靠服务质量而非锁定获利。

## 6. 三阶段产品路径

| 阶段 | 产品承诺 | 成功条件 |
|---|---|---|
| 现在—12 个月 | 最可信、最能把任务做完的个人科研 Agent 工作台 | 写作/PDF/证据主链路稳定；核心任务完成率与复用率提升 |
| 12—24 个月 | 实验室研究资产与 Agent 协作平台 | 多成员权限、共享资产、标准工作流、团队审计成立 |
| 24—36 个月 | 可部署、可扩展的科研 AI 基础设施 | 机构级身份、安全、私有部署、API 与生态治理成熟 |

对外可以讲“通往 Research AI OS”，但每一阶段都必须交付独立价值，不能用宏大愿景替代产品可靠性。

## 7. 最终定义

**一句话定位**：

> Scholar Harness 是一个本地优先、证据驱动的科研 Agent 工作台，帮助研究者把分散的文献、数据、工具和写作流程转化为可追溯、可复用的科研成果。

**英文建议**：

> Scholar Harness is a local-first, evidence-grounded research agent workspace that turns literature, data, tools, and workflows into traceable and reusable research outputs.
