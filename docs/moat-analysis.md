# Scholar Harness 护城河分析

> 核心判断：大模型能力会快速商品化，单个 Prompt、单一模型接入和普通聊天界面都不能构成长期壁垒。Scholar Harness（下称 SH）的护城河应建立在 **科研资产图谱、可靠执行内核、证据质量评估、生态标准和组织治理** 的组合上。

## 1. 竞争前提

未来 3 年，OpenAI、Google、Anthropic 等模型公司会持续增强检索、文件理解、代码执行、长任务和 Agent 能力。SH 不应试图在基础模型能力上正面对抗，而应占据模型公司不容易深耕的部分：

- 跨文献、PDF、数据、统计、写作和投稿的科研全流程；
- 句子—证据—引用—来源之间的可追溯关系；
- 本地工具、R/Python/Office、机构数据和科研权限的可靠编排；
- 针对科研结果的专业质量标准、评估集和恢复机制；
- 从个人工作流扩展到课题组与机构治理。

因此，SH 的竞争单位不是“一次回答”，而是一个完成、可复核、可恢复且可复用的科研任务。

## 2. 与主要竞争者的边界

| 竞争者 | 强项 | SH 不应正面对抗的部分 | SH 可形成差异的位置 |
|---|---|---|---|
| OpenAI / Anthropic | 基础模型、通用 Agent、代码与工具调用 | 模型智能、通用聊天、通用编程助手 | 科研证据链、专业评估、跨工具任务状态、本地与机构治理 |
| Google | 搜索、Scholar、Workspace、云生态与分发 | 通用检索、办公套件、云基础设施 | 模型与供应商中立、本地优先、跨来源证据资产、科研专项工作流 |
| Notion | 文档协作、知识库、团队采用 | 通用协作文档和页面搭建 | 文献真实性、引用约束、统计分析、科研任务执行和审计 |
| Zotero / EndNote | 文献管理、格式、用户基础与引用生态 | 传统文献收藏和格式标准 | 从“管理文献”升级到“基于证据完成研究任务” |
| 垂直论文写作工具 | 上手快、生成直接 | 低价改写、摘要和模板生成 | 可验证证据、深工作流、数据分析、资产复用与机构部署 |

竞争策略应是连接而不是替代：把 Zotero、EndNote、浏览器、Office、R/Python 和大模型变成 SH 的可编排能力。

## 3. 五类候选护城河

### 3.1 代码壁垒：单独较弱，系统组合后才有价值

界面、普通 CRUD、模型适配器和单个工作流很容易复制。真正难复制的是：

- 长任务的状态持久化、恢复、转向和失败降级；
- 多 Agent、Skill、MCP、本地文件与权限之间的统一执行契约；
- 文献证据、引用、数据和产物的统一身份与血缘；
- 在打包桌面环境中稳定运行的跨平台工具链。

因此代码壁垒来自可靠性与系统复杂度，而不是代码保密本身。

### 3.2 数据壁垒：只能来自获授权的结构化结果与评估数据

用户上传的 PDF、论文、实验数据和聊天内容属于用户，不应默认成为公司的训练资产。可合法沉淀的数据包括：

- 用户明确授权的匿名化质量反馈；
- 检索候选、接受/拒绝结果和理由；
- 引用支撑度的人工复核标签；
- 不包含原始敏感内容的失败类型和恢复路径；
- 公开数据形成的基准测试集。

数据壁垒的目标不是“拥有最多论文”，而是拥有最能衡量科研任务是否正确完成的评估体系。

### 3.3 工作流壁垒：近期最强

SH 已具备形成工作流壁垒的基础：两级 Agent、混合检索、PDF Wiki、Meta、文献计量、R 作图、Auto Research、Skill/MCP 和本地工具。下一步不是继续堆入口，而是把高价值任务做成可测量的闭环：

1. 输入材料与目标；
2. 生成计划和证据需求；
3. 检索、分析和工具执行；
4. 证据与引用校验；
5. 生成可交付产物；
6. 记录过程、版本和人工修订；
7. 下次任务复用。

高完成率、低返工率和稳定恢复能力比功能数量更难复制。

### 3.4 网络效应：需要人为设计

开源本身不会自动产生网络效应。应围绕以下对象建立网络：

- 可验证的 Skill、插件、模板和数据连接器；
- 作者、维护者、机构和工作流的信誉；
- 统一的能力清单、权限、输入输出和测试规范；
- 社区贡献与商业市场之间的收益分配；
- 实验室内部可授权复用的研究资产和标准流程。

网络效应来自兼容性、信誉和复用，而不是上传文件数量。

### 3.5 行业壁垒：长期最重要

科研场景包含大量通用模型不愿长期维护的细节：

- 引用是否真实且足以支撑原子主张；
- DOI、题名、年份、期刊和尾注格式的一致性；
- Meta 分析效应量、数据结构和统计假设；
- 图表、处理组颜色、panel 和投稿规范；
- 学科差异、伦理、隐私、版权和机构审计。

把这些规则固化为契约、评估和可执行工作流，才能形成行业壁垒。

## 4. 建议的护城河栈

### 第一层：Research Asset Graph（科研资产图谱）

统一连接：项目、文献、PDF、句子、论点、引用、数据集、变量、分析、图表、草稿、版本、工具调用和人工决策。它不是可视化网状图，而是所有工作流共享的结构化事实层。

### 第二层：Research Execution Kernel（科研执行内核）

统一处理意图路由、上下文按需装载、任务队列、权限、工具调用、状态恢复、成本预算和产物登记。主页、Meta、计量和 PDF 专用入口都应复用该内核。

### 第三层：Evidence & Evaluation Engine（证据与评估引擎）

建立引用真实性、句子支撑度、检索召回、数据完整性、统计合理性和交付质量的评估集。每个关键任务有可回归的成功标准。

### 第四层：生态标准与信誉网络

开放能力清单、接口规范、测试工具和轻量运行时；对 Skill、MCP、模板和连接器实施签名、权限、兼容性与质量评级。

### 第五层：组织治理与商业控制面

包括团队空间、权限、审计、配额、策略、私有部署、连接器管理、管理员控制台和服务等级。这是 Lab/Enterprise 付费的核心。

## 5. 必须保护与可以开放的内容

### 必须保护

- 生产级任务编排、上下文编译和恢复策略；
- 证据质量模型、评估集、阈值与质量运营数据；
- 组织治理、授权、计费、风控和商业控制面；
- 企业连接器、部署自动化和服务运营方法；
- 获授权形成的匿名化反馈数据及其学习管线。

### 适合开放

- Research Asset Graph 的公共 schema 与导入导出规范；
- Skill/MCP/连接器 SDK、权限清单和测试工具；
- 本地轻量运行时、示例工作流和公开基准；
- 与 Zotero、Office、R/Python、公开数据库的通用连接器；
- 社区版插件市场协议和兼容性认证流程。

开放标准能扩大生态，私有生产内核负责把生态能力稳定地转化为结果。

## 6. 24 个月护城河路线

### 0–6 个月：从功能集合变成可靠产品

- 统一任务状态、上下文装载、文件血缘和错误恢复；
- 选择 3 个灯塔工作流：证据核验写作、PDF 证据库、Meta/数据分析；
- 建立端到端评估集和发布门禁；
- 明确根许可证、第三方许可证和用户数据规则。

### 6–12 个月：形成资产复用与专业信誉

- 上线 Research Asset Graph 最小闭环；
- 让项目资产可被不同工作流复用而不重复注入 Prompt；
- 推出带签名、测试和权限的 Skill/插件注册表；
- 用真实用户修订数据提升证据与任务质量评估。

### 12–24 个月：建立组织网络与标准

- 推出 Lab 空间、标准流程、审计和私有知识连接器；
- 与实验室、期刊服务商、科研软件和数据平台合作；
- 发布公开兼容性标准和基准榜单；
- 让机构的模板、规则和研究资产成为长期留存来源。

## 7. 护城河指标

| 层级 | 核心指标 |
|---|---|
| 执行内核 | 任务成功率、恢复成功率、人工重跑率、平均完成时间 |
| 证据质量 | 引用可验证率、支撑度人工一致率、错误引用率、检索召回率 |
| 资产图谱 | 跨任务资产复用率、重复上传/重复计算下降率、可追溯产物占比 |
| 生态 | 通过验证的扩展数、活跃维护者、安装后留存、兼容性通过率 |
| 商业 | Pro 转化、Lab 扩张、净收入留存、毛利、支持成本 |

## 8. 主要威胁与应对

| 威胁 | 应对 |
|---|---|
| 模型厂商原生 Agent 覆盖常见功能 | 保持模型中立，专注证据、科研资产、质量和组织治理 |
| 功能过多导致可靠性下降 | 以灯塔工作流和评估门禁管理路线图 |
| 开源后被复制 | 开放标准与边缘能力，保护生产内核、评估和商业控制面 |
| 用户数据与版权风险 | 本地优先、明确授权、可删除、可导出、来源与许可登记 |
| 高模型成本压缩毛利 | 动态上下文、缓存、分层模型、任务预算和自带 Key |
| 机构定制拖垮团队 | 配置化、插件化和标准产品优先，定制必须可复用 |

## 9. 最终判断

SH 最有可能形成的护城河不是“比别人更会写论文”，而是：

> 用可验证的科研资产图谱和可靠执行内核，把模型、文献、数据、工具与组织规则变成可追溯、可复用、可治理的科研成果。

如果不能把当前大量功能收敛到上述五层，复杂度只会成为成本；如果能够收敛，当前的跨工作流广度才会转化为难以复制的系统优势。
