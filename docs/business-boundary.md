# Scholar Harness 商业边界设计

> 收费边界应围绕“更复杂的任务完成、更可信的证据、更高的资产复用和更强的组织治理”，而不是简单按按钮数量或聊天字数切割。

## 1. 商业化原则

1. 免费版必须能完成一条真实闭环，否则无法形成口碑和生态。
2. 基础数据导入、导出和删除不应收费，避免用数据锁定制造收入。
3. Pro 收费来自自动化深度、可信度与资产复用，不是换皮模型额度。
4. Lab 收费来自团队协作、治理和标准化，不只是席位折扣。
5. Enterprise 收费来自安全、集成、部署和责任边界，不只是“私有安装”。
6. 模型/API 成本与软件订阅分开管理，支持 BYOK；上游模型余额不足不等同于 Scholar Harness 软件额度。
7. 所有版本保留来源标识、AI 内容提示和基本安全门禁。

当前软件套餐统一按月度、季度和年度有效期授权，不设置“可处理字符数”或“可上传文件数”等数字额度。字数、文件数和调用次数仅可用于用户历史记录、性能观测和成本分析，不得作为拒绝软件功能的门禁。未来如引入 Free/Pro/Lab/Enterprise，应基于能力和组织治理边界设计 entitlement，而不是重新引入字符配额。

## 2. 版本设计

### 2.1 Free：完成首个可信科研闭环

**目标**：用户增长、个人验证、开发者生态。

包含：

- 本地单用户工作区与基础项目管理；
- 基础聊天、文件阅读和常见格式导入导出；
- 有限规模的文献库与 PDF 解析；
- BM25 检索；用户配置 Embedding 后可在合理规模内使用本地级联检索；
- 基础 Skill/插件安装与运行；
- 一个可完整完成的“文献 → 证据 → 草稿”流程；
- BYOK 模型接入；
- 数据导出、备份与删除。

限制建议：

- 同时活跃项目数、自动化任务并发数和索引规模；
- 高级证据核验批次、长任务恢复历史和专业工作流模板；
- 无团队共享、组织治理和企业连接器；
- 官方托管模型只提供少量试用额度。

不要限制：基础数据可携带性、引用来源显示、用户数据删除、安全更新。

### 2.2 Pro：个人科研任务稳定完成

**目标用户**：研究生、博士后、独立研究者、高频论文作者。

核心收费价值：

- 更大规模的 Embedding 文献库和 PDF Wiki；
- BM25 → Embedding → reranker 完整检索链；
- 批量句子级证据核验、引用审计和支撑度报告；
- Auto Research、文献计量、Meta、数据分析/R 作图高级流程；
- 长任务持久化、并发、断点续跑和更长历史；
- 跨项目研究资产复用和高级长期记忆；
- 高级期刊/章节 Skill、自动质量门禁和版本比较；
- 多模型路由、成本控制、优先队列和官方托管额度选项；
- 构造 Agent 的个人隔离功能包与回滚。

用户愿意付费的原因应是：少返工、少错引、复杂任务能做完、旧资产能复用，而不是“能调用更贵的模型”。

建议公开价格带（需用户访谈验证）：

- 中国个人：¥49–99/月，¥399–699/年；
- 国际个人：US$12–25/月；
- 托管模型额度单独充值或设公平使用上限，BYOK 用户不重复为模型付费。

### 2.3 Lab：实验室研究资产与协作

**目标用户**：PI、课题组、联合实验室和小型研究中心。

核心能力：

- 团队空间、成员与项目权限；
- 共享文献、证据、数据字典、期刊模板和实验室 Skill；
- 私有 Agent、标准工作流和管理员发布/撤回；
- 任务分派、审阅、批注、版本与审批；
- 团队证据图谱与重复研究资产发现；
- 模型/API 预算、额度和成本归集；
- 审计日志、备份、成员离组和资产移交；
- 实验室连接器、共享插件和内网资源访问策略；
- 管理面板和基础支持。

收费方式：平台费 + 活跃成员席位，或按团队规模分档。建议从 ¥9,800–39,800/年验证，而不是按个人版简单乘人数。

### 2.4 Enterprise：机构级科研 AI 基础设施

**目标用户**：高校、研究院、医院科研部门、企业研发中心。

核心能力：

- 私有部署、专有云或混合部署；
- SSO/SAML/OIDC、SCIM、RBAC/ABAC；
- KMS、密钥托管、数据区域和保留策略；
- 模型网关、私有模型、供应商白名单和成本策略；
- 全量审计、合规导出、DLP 和安全事件流程；
- 机构知识库、数据源和科研管理系统连接；
- 高可用、监控、升级通道、SLA 与专属支持；
- 私有市场、内部 Skill/插件审批和签名；
- 定制评估、部署培训和治理咨询。

收费方式：年度平台许可 + 部署实施 + 支持服务 + 可选使用量。建议从 ¥20 万/年起验证，复杂私有化和集成单独报价。

## 4. 计费边界

建议把账单拆为三部分：

1. **软件订阅**：为工作流、证据系统、资产复用和治理付费；
2. **模型与计算**：BYOK 为零平台加价或收取小额网关服务费；托管模型按透明额度计费；
3. **专业服务**：私有部署、连接器、迁移、培训和定制评估。

不建议：

- 仅按 Token 加价，容易与模型厂商直接竞争；
- 隐藏模型成本；
- 对导出和删除收费；
- 用“永久版无限额度”承诺不可持续的云服务；
- 把每个小功能做成付费开关，造成产品碎片化。

## 5. 商业保护与用户信任

收费不应以牺牲信任为代价：

- 用户原始资料不用于训练，除非单独、明确、可撤销地同意；
- 企业数据不进入公共模型优化；
- 插件和 Skill 权限透明；
- 订阅到期后允许只读、导出和删除；
- 重要分析记录包含模型、版本、工具和来源；
- 结果不保证发表或通过审稿，避免虚假承诺。

## 6. 商业指标

### 个人业务

- 首周有效任务完成率；
- Free → Pro 激活率；
- Pro 90 天留存；
- 每个付费用户的可追溯任务数；
- 模型成本占收入比例与 BYOK 占比。

### 团队与企业

- 单个 Lab 的活跃项目与共享资产复用率；
- 席位扩张率、续费率和净收入留存；
- 私有 Skill/工作流实际使用率；
- 部署周期、支持工时和毛利；
- 安全与审计问题响应时间。

## 7. 推荐推进顺序

1. 在现有按期订阅基础上抽象 Free/Pro 权益，保持字符数和文件数不限；
2. 以“证据核验 + 长任务完成 + 研究资产复用”验证个人付费；
3. 选择 5–10 个真实实验室共创 Lab 权限与知识库；
4. 在 Lab 稳定前不做大规模高校私有化销售；
5. 企业项目坚持标准产品优先，定制代码必须可配置化或插件化。
