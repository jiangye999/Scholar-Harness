# 智能记忆补充系统使用说明

## 📋 概述

ScholarClaw 现在支持**智能增量补充**记忆系统，而非简单的覆盖。当您上传文件或进行对话时，AI 会自动：
1. **提取**关键信息
2. **去重**现有记忆
3. **补充**新细节
4. **更新**冲突信息

---

## 🧠 记忆板块（17 个字段）

### 一、研究概况（3 个字段）
| 字段 | 说明 | 示例 |
|------|------|------|
| `research_topic` | 研究主题 | 华北平原玉米 N2O 排放研究 |
| `target_journal` | 目标期刊 | Journal of Environmental Management |
| `key_concepts` | 关键概念 | 玉米轮作，氮管理，温室气体排放 |

### 二、实验信息（5 个字段）✨新增
| 字段 | 说明 | 示例 |
|------|------|------|
| `experimental_design` | 实验设计概述 | 田间试验，3 个处理 |
| `experiment_summary` | 实验资料总结 | 地点、气候、土壤、处理详情 |
| `methodology_details` | 【新】方法学细节 | 试剂浓度、处理时间、温度等 |
| `equipment_info` | 【新】设备信息 | 仪器型号、厂家、参数 |
| `sample_info` | 【新】样本信息 | 采样日期、位置、存储条件 |

### 三、数据信息（4 个字段）✨新增
| 字段 | 说明 | 示例 |
|------|------|------|
| `data_status` | 数据状态 | 有实验数据 |
| `data_summary` | 数据详细总结 | 排放量、统计结果等 |
| `structured_data` | 【新】结构化数据 | JSON 格式的统计表 |
| `statistical_results` | 【新】统计结果 | ANOVA、p 值、效应量 |
| `data_visualization` | 【新】图表说明 | Figure 1-说明文字 |

### 四、写作进度（5 个字段）✨新增
| 字段 | 说明 | 示例 |
|------|------|------|
| `writing_task` | 当前写作任务 | Discussion |
| `user_preferences` | 用户偏好 | 特殊写作要求 |
| `writing_progress` | 写作进度 | 已完成引言和方法 |
| `completed_chapters` | 已完成章节 | 引言：300 字；方法：500 字 |
| `pending_chapters` | 待完成章节 | 结果：重点写排放对比 |
| `draft_progress` | 【新】草稿进度 | 引言已写 2 稿，方法写到第 3 段 |

## 🔄 智能合并工作原理

### 合并原则
1. **去重**：相同信息只保留一份
2. **补充**：新细节自然融入现有内容
3. **更新**：冲突信息以新的为准
4. **简洁**：合并后连贯，无冗余过渡词
5. **完整**：保留所有重要信息和数值

### 工作流程
```
用户上传文件/对话
       ↓
AI 提取关键信息
       ↓
检测是否有现有记忆
       ↓
     有记忆？
    ↙     ↘
   是       否
   ↓         ↓
AI 智能合并  直接保存
   ↓
更新 memory.json
```

### 示例

**现有记忆**：
```
研究在中国农业大学曲周实验站开展，年均降水量 556mm...
```

**用户提供新信息**：
```
我们使用静态暗箱 - 气相色谱法测定 N2O 排放，采样频率为每周一次
```

**合并后**：
```
研究在中国农业大学曲周实验站开展，年均降水量 556mm...采用静态暗箱 - 气相色谱法测定 N2O 排放，采样频率为每周一次
```

## 📁 支持的文件类型

### 1. 论文草稿（.docx, .pdf）
**提取内容**：
- 已完成章节
- 草稿进度
- 写作风格偏好

**如何使用**：
1. 上传论文草稿
2. AI 自动提取进度
3. 更新 `draft_progress` 和 `completed_chapters`

### 2. 实验方案（.docx, .pdf, .txt）
**提取内容**：
- 方法学细节
- 试剂和仪器
- 实验步骤

**如何使用**：
1. 上传实验方案
2. AI 提取详细方法
3. 更新 `methodology_details` 和 `equipment_info`

### 3. 数据文件（.xlsx, .csv, .txt）
**提取内容**：
- 结构化数据（统计值）
- 统计结果
- 数据表说明

**如何使用**：
1. 上传数据文件
2. AI 提取关键统计值
3. 更新 `structured_data` 和 `statistical_results`

### 4. 文献导出（.ris, .bib, .txt）
**提取内容**：
- 文献信息
- 研究关键词
- 重要发现

**如何使用**：
1. 上传 Web of Science/知网导出文件
2. AI 解析文献信息
3. 更新 `key_concepts` 和 `important_findings`

## 🎯 使用场景

### 场景 1：上传论文草稿 → 智能补充草稿进度

**操作**：
1. 对话框上传 `draft_v1.docx`
2. 说："这是我写的初稿，请记录进度"

**AI 会自动**：
- 分析已完成的章节
- 提取各章节字数
- 更新 `draft_progress`："引言已完成（800 字），方法写到第 2 节（500 字）"
- 更新 `completed_chapters`："引言：介绍研究背景和意义"

---

### 场景 2：上传实验方案 → 补充方法细节

**操作**：
1. 上传 `实验方案.pdf`
2. 说："请记录实验方法细节"

**AI 会自动**：
- 提取试剂浓度、处理时间
- 提取仪器型号和参数
- 更新 `methodology_details`："土壤硝态氮使用连续流动分析仪测定..."
- 更新 `equipment_info`："气相色谱仪：Agilent 7890B，检测器：FID..."

---

### 场景 3：上传数据表 → 补充统计结果

**操作**：
1. 上传 `N2O_emissions.xlsx`
2. 说："这是今年的监测数据"

**AI 会自动**：
- 提取各处理的排放值
- 提取统计检验结果
- 更新 `structured_data`：`{"Spr_O": "1.77", "Sum_O": "4.86"}`
- 更新 `statistical_results`："ANOVA 显示处理间差异显著（F=15.3, p<0.001）"

---

### 场景 4：对话中提供信息 → 实时补充

**操作**：
直接在对话中说：
```
"我们使用了 3 个重复，每个处理 5 个小区，随机区组设计"
```

**AI 会自动**：
- 识别这是实验设计信息
- 检查现有 `experimental_design`
- 智能合并："田间试验，随机区组设计，3 个重复，每个处理 5 个小区..."

## 🔧 手动管理记忆

### 查看当前记忆
```bash
GET /api/memory/web-user
```

### 手动更新（带智能合并）
```javascript
POST /api/memory/web-user/update
{
  "experimentSummary": "新的实验信息",
  "dataSummary": "新的数据信息",
  "merge": true  // 启用 AI 智能合并
}
```

### 搜索记忆
```bash
GET /api/memory/web-user/search?q=N2O
```

## ✅ 验证智能合并是否生效

### 方法 1：查看日志
```
[Memory] Merging experiment_summary with existing memory...
[Memory] experiment_summary merged successfully, length: 458
```

### 方法 2：检查 memory.json
查看 `memory.json` 中是否：
1. 内容长度增加（补充了新细节）
2. 保留了旧信息（非覆盖）
3. 时间戳更新

### 方法 3：直接询问 AI
```
"我的实验信息记忆里有什么？"
```

## ⚠️ 注意事项

1. **智能合并需要 API 调用**：确保配置了 API URL 和 Key
2. **大文件上传**：PDF>10MB 可能导致提取慢
3. **JSON 格式数据**：`structured_data` 必须是有效 JSON
4. **记忆不会丢失**：所有更新都带时间戳，可追溯

## 🚀 最佳实践

### ✅ 推荐做法
- 定期上传最新草稿和方案
- 对话中提及关键细节
- 使用专业术语（便于 AI 识别）
- 上传数据后请 AI 总结

### ❌ 避免做法
- 上传模糊/扫描件（AI 难以提取）
- 期望一次性处理大量文件
- 忽视 AI 的确认回复
