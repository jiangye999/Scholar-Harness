# Scholar Harness 数据安全管理制度

**生效日期**：2026年4月10日  
**最后更新日期**：2026年4月10日  
**版本号**：V1.0  
**密级**：内部公开

---

## 第一章 总则

### 1.1 目的

为保障 Scholar Harness 用户数据安全，防范数据泄露、篡改、丢失等风险，根据《中华人民共和国数据安全法》《中华人民共和国个人信息保护法》等法律法规，制定本制度。

### 1.2 适用范围

本制度适用于：
- Scholar Harness 运营主体所有员工
- 与数据接触的第三方合作伙伴
- 所有用户数据的收集、存储、使用、共享、删除等全生命周期

### 1.3 基本原则

1. **合法正当原则**：数据收集、使用符合法律法规
2. **最小必要原则**：仅收集、使用必要的数据
3. **安全保护原则**：采取充分安全措施保护数据
4. **责任明确原则**：明确数据安全责任主体
5. **持续改进原则**：定期评估、持续优化安全措施

## 第二章 数据分类分级

### 2.1 数据分类

根据数据性质，将数据分为以下类别：

| 类别 | 包含内容 | 示例 |
|-----|---------|------|
| **用户身份信息** | 识别用户身份的信息 | 邮箱、手机号、用户名 |
| **认证凭据信息** | 用于身份验证的信息 | 密码hash、API密钥、token |
| **用户内容数据** | 用户产生的内容 | 论文内容、研究材料、草稿 |
| **服务使用数据** | 服务使用相关数据 | 使用记录、会话日志、AI生成日志 |
| **交易支付数据** | 支付相关数据 | 订单记录、支付记录、退款记录 |
| **系统运维数据** | 系统运行相关数据 | 日志、监控数据、配置信息 |

### 2.2 数据分级

根据数据敏感程度，将数据分为以下级别：

| 级别 | 定义 | 包含数据 | 保护要求 |
|-----|------|---------|---------|
| **极敏感** | 泄露将造成严重损害 | 密码hash、API密钥、支付信息 | 最高级别保护，加密存储，严格访问控制 |
| **敏感** | 泄露将造成较大损害 | 用户内容数据、邮箱、手机号 | 高级别保护，加密存储，访问审批 |
| **内部** | 泄露将造成一般损害 | 使用记录、会话日志 | 中级别保护，访问控制 |
| **公开** | 可公开的信息 | 官网公开内容 | 基础保护 |

### 2.3 数据资产清单

**建立数据资产清单**，包含以下信息：
- 数据名称
- 数据类别
- 数据级别
- 数据来源
- 存储位置
- 负责人
- 保护措施
- 保存期限

**更新频率**：每季度更新一次

## 第三章 数据安全管理要求

### 3.1 数据收集安全要求

#### 3.1.1 收集原则

- **知情同意**：收集前告知用户并获得同意（隐私政策）
- **最小必要**：仅收集服务必要的数据
- **合法正当**：符合法律法规要求

#### 3.1.2 收集规范

- 通过合法途径收集数据
- 不得诱导、欺骗用户提供数据
- 不得收集与服务无关的数据
- 敏感数据需明确告知并单独同意

### 3.2 数据存储安全要求

#### 3.2.1 存储位置

| 数据类型 | 存储位置 | 存储方式 |
|---------|---------|---------|
| 用户身份信息 | 云端数据库 | 加密存储 |
| 认证凭据信息 | 云端数据库 | 强加密存储 |
| 用户内容数据 | 本地+云端 | 可选加密 |
| 服务使用数据 | 本地+云端 | 明文（日志） |
| 交易支付数据 | 云端数据库 | 加密存储 |
| 系统运维数据 | 云端日志系统 | 明文 |

#### 3.2.2 加密要求

**极敏感数据**：
- 使用 AES-256 或更强加密算法
- 密钥单独存储，定期更换（每90天）
- 加密密钥不得与数据同存

**敏感数据**：
- 使用 AES-128 或更强加密算法
- 密钥管理规范，定期更换（每180天）

#### 3.2.3 访问控制

**数据库访问**：
- 仅授权人员可访问
- 访问需审批并记录
- 最小权限原则

**本地文件访问**：
- 会话数据仅用户本人可访问
- 草稿数据仅用户本人可访问

### 3.3 数据使用安全要求

#### 3.3.1 使用原则

- **目的限制**：仅用于告知的目的
- **权限控制**：仅授权人员可使用
- **操作记录**：记录所有操作

#### 3.3.2 使用规范

- 不得超范围使用数据
- 不得擅自复制、导出数据
- 敏感数据使用需审批
- 定期清理不必要的数据

### 3.4 数据共享安全要求

#### 3.4.1 共享原则

- **必要性**：仅共享必要数据
- **最小化**：共享最小数据量
- **安全传输**：使用加密通道
- **协议约束**：签订数据保护协议

#### 3.4.2 共享审批

**内部共享**：
- 跨部门共享需部门负责人审批
- 记录共享内容和目的

**外部共享**：
- 第三方共享需法务审批
- 签订数据保护协议
- 评估第三方安全能力
- 定期审计第三方数据处理

#### 3.4.3 数据跨境传输

**跨境传输评估**：
- 评估跨境传输必要性
- 评估数据安全风险
- 告知用户并获同意

**跨境传输保护**：
- 仅传输必要数据
- 使用加密通道
- 选择合规的境外服务

### 3.5 数据删除安全要求

#### 3.5.1 删除场景

- 用户申请删除
- 数据保存期限到期
- 服务终止
- 法律法规要求

#### 3.5.2 删除规范

**普通删除**：
- 标记删除，保留30天
- 30天后物理删除

**立即删除**：
- 用户申请账户注销
- 发现违法数据
- 数据泄露风险

**删除验证**：
- 删除后验证数据不可恢复
- 记录删除操作日志

## 第四章 访问控制管理

### 4.1 访问权限管理

#### 4.1.1 权限分级

| 角色 | 权限范围 | 审批要求 |
|-----|---------|---------|
| **管理员** | 全部数据访问权限 | CEO审批 |
| **运营人员** | 用户服务数据访问权限 | 部门负责人审批 |
| **开发人员** | 开发测试数据访问权限 | 技术负责人审批 |
| **客服人员** | 用户咨询数据访问权限 | 部门负责人审批 |

#### 4.1.2 权限申请流程

```
申请权限 → 部门负责人审批 → 数据安全负责人审批 → 权限分配 → 记录存档
```

#### 4.1.3 权限定期审查

- 每季度审查一次权限
- 离职员工立即撤销权限
- 岗位变更及时调整权限

### 4.2 身份认证管理

#### 4.2.1 认证方式

- **管理员**：多因素认证（MFA）+ 强密码
- **其他人员**：强密码 + 定期更换（每90天）

#### 4.2.2 密码要求

- 长度：至少12位
- 复杂度：大小写字母+数字+特殊字符
- 不得使用：常见密码、个人信息
- 定期更换：每90天

### 4.3 访问日志管理

#### 4.3.1 日志记录内容

- 访问时间
- 访问人员
- 访问数据类型
- 访问操作（查询、修改、删除）
- 访问结果

#### 4.3.2 日志保存期限

- 普通访问日志：1年
- 敏感数据访问日志：2年
- 安全事件日志：5年

## 第五章 数据加密管理

### 5.1 传输加密

**要求**：
- 所有数据传输使用 HTTPS（TLS 1.2+）
- API 调用使用加密通道
- 文件上传下载使用加密传输

**证书管理**：
- 使用可信 CA 颁发的证书
- 证书定期更新（到期前30天）
- 私钥安全存储

### 5.2 存储加密

**数据库加密**：
- 敏感字段加密存储
- 使用应用层加密（而非数据库层）
- 加密密钥单独管理

**文件加密**：
- 用户上传文件可选加密
- 敏感文件强制加密
- 备份文件加密

### 5.3 密钥管理

**密钥生成**：
- 使用密码学安全随机数生成器
- 密钥长度满足安全要求

**密钥存储**：
- 密钥与加密数据分离存储
- 使用密钥管理系统（KMS）
- 密钥加密存储

**密钥轮换**：
- 定期更换密钥（90-180天）
- 密钥泄露立即更换
- 记录密钥使用历史

## 第六章 数据备份管理

### 6.1 备份策略

#### 6.1.1 备份范围

| 数据类型 | 备份频率 | 保存期限 | 备份方式 |
|---------|---------|---------|---------|
| 用户账户数据 | 每日 | 30天 | 增量备份 |
| 用户内容数据 | 每日 | 7天 | 增量备份 |
| 系统配置数据 | 每日 | 30天 | 全量备份 |
| 数据库数据 | 每日 | 30天 | 增量备份 |
| 日志数据 | 每日 | 7天 | 增量备份 |

#### 6.1.2 备份存储

- **存储位置**：异地备份（不同机房/云服务商）
- **存储加密**：备份文件加密存储
- **访问控制**：仅授权人员可访问备份

#### 6.1.3 备份验证

- 每月进行一次备份恢复测试
- 验证备份数据完整性
- 记录测试结果

### 6.2 恢复机制

#### 6.2.1 恢复场景

- 数据丢失
- 数据损坏
- 系统故障
- 灾难恢复

#### 6.2.2 恢复流程

```
发现数据问题 → 评估影响范围 → 选择恢复点 → 执行恢复 → 验证恢复结果 → 记录恢复日志
```

#### 6.2.3 恢复时间目标（RTO）

- 关键数据：4小时内恢复
- 重要数据：24小时内恢复
- 一般数据：72小时内恢复

## 第七章 应急响应管理

### 7.1 应急响应组织

#### 7.1.1 组织架构

- **应急响应组长**：CEO 或授权负责人
- **技术负责人**：技术总监
- **安全负责人**：数据安全负责人
- **客服负责人**：客服主管
- **法务负责人**：法务顾问

#### 7.1.2 职责分工

- 组长：决策、协调、对外沟通
- 技术负责人：技术处理、系统恢复
- 安全负责人：安全评估、事件分析
- 客服负责人：用户沟通、公告发布
- 法务负责人：合规评估、监管报告

### 7.2 应急响应流程

#### 7.2.1 事件分级

| 级别 | 定义 | 示例 | 响应时间 |
|-----|------|------|---------|
| **一级（特大）** | 大规模数据泄露、系统瘫痪 | 10万+用户数据泄露 | 1小时内响应 |
| **二级（重大）** | 较大规模数据泄露、部分服务中断 | 1万+用户数据泄露 | 2小时内响应 |
| **三级（较大）** | 小规模数据泄露、服务异常 | 1000+用户数据泄露 | 4小时内响应 |
| **四级（一般）** | 个别数据泄露、服务波动 | 少量用户数据泄露 | 8小时内响应 |

#### 7.2.2 响应流程

```
事件发现 → 初步评估 → 应急启动 → 应急处置 → 事件调查 → 总结改进
```

**详细流程**：

1. **事件发现**（0-30分钟）
   - 监控系统告警
   - 用户投诉反馈
   - 内部发现异常
   - 记录发现时间和情况

2. **初步评估**（30分钟-1小时）
   - 确认事件真实性
   - 评估事件级别
   - 确定影响范围
   - 通知应急响应团队

3. **应急启动**（1-2小时）
   - 召开应急会议
   - 启动应急预案
   - 分配任务和职责
   - 启动日志记录

4. **应急处置**（2-24小时）
   - 隔离受影响系统
   - 阻断攻击源
   - 修复安全漏洞
   - 恢复系统服务
   - 通知受影响用户

5. **事件调查**（24-72小时）
   - 收集证据
   - 分析原因
   - 评估损失
   - 追究责任

6. **总结改进**（72小时-7天）
   - 撰写事件报告
   - 分析根本原因
   - 制定改进措施
   - 更新应急预案
   - 向监管报告（如需要）

### 7.3 应急预案

#### 7.3.1 数据泄露应急预案

**发现后立即**：
1. 隔离受影响系统
2. 阻断数据泄露渠道
3. 保存证据日志

**24小时内**：
1. 分析泄露原因
2. 确认泄露数据范围
3. 通知受影响用户
4. 向监管报告（如需要）

**72小时内**：
1. 修复安全漏洞
2. 加强安全措施
3. 撰写事件报告

#### 7.3.2 数据丢失应急预案

**发现后立即**：
1. 停止相关服务
2. 启动备份恢复
3. 评估丢失范围

**4小时内**：
1. 从备份恢复数据
2. 验证数据完整性
3. 恢复服务

**24小时内**：
1. 分析丢失原因
2. 加强备份措施
3. 通知受影响用户

## 第八章 安全审计管理

### 8.1 内部审计

#### 8.1.1 审计频率

- **季度审计**：常规安全检查
- **专项审计**：发现安全隐患后
- **年度审计**：全面安全评估

#### 8.1.2 审计内容

- 数据访问权限
- 数据使用规范
- 安全措施执行
- 应急预案演练
- 安全培训记录

#### 8.1.3 审计报告

- 审计发现
- 风险评估
- 整改建议
- 整改期限

### 8.2 外部审计

#### 8.2.1 审计要求

- 每年至少一次外部安全审计
- 选择有资质的安全机构
- 审计报告存档备查

#### 8.2.2 审计内容

- 系统安全评估
- 渗透测试
- 合规性评估
- 数据安全评估

## 第九章 人员安全管理

### 9.1 人员招聘

#### 9.1.1 背景调查

- 关键岗位需进行背景调查
- 核实学历、工作经历
- 评估诚信记录

#### 9.1.2 保密协议

- 入职前签订保密协议
- 明确保密义务和责任
- 明确违约后果

### 9.2 安全培训

#### 9.2.1 培训计划

| 培训类型 | 培训对象 | 培训频率 | 培训内容 |
|---------|---------|---------|---------|
| 安全意识培训 | 全体员工 | 每季度 | 数据安全法规、安全意识 |
| 专业技能培训 | 技术人员 | 每季度 | 安全技术、应急处理 |
| 合规培训 | 管理人员 | 每半年 | 法律法规、合规要求 |

#### 9.2.2 培训考核

- 培训后进行考核
- 考核不合格需补训
- 记录培训档案

### 9.3 离职管理

#### 9.3.1 离职流程

- 立即撤销所有访问权限
- 回收公司设备和账号
- 确认数据删除
- 签署离职保密承诺

## 第十章 责任与惩罚

### 10.1 责任划分

- **CEO**：数据安全总责任人
- **数据安全负责人**：数据安全直接责任人
- **部门负责人**：部门数据安全责任人
- **员工**：各自操作的数据安全责任人

### 10.2 违规处理

#### 10.2.1 违规行为

- 未经授权访问数据
- 擅自复制、导出数据
- 泄露用户数据
- 未执行安全措施
- 发现安全隐患未报告

#### 10.2.2 处理措施

- **轻微违规**：警告、扣绩效、重新培训
- **严重违规**：降职、调岗、解除劳动合同
- **违法违规**：追究法律责任
