# 构造需求与验收契约

1. 用一句话复述目标，并列出明确不做的内容。
2. 标出入口、用户操作、输入数据、输出结果、持久化状态和失败恢复。
3. 把模糊要求转换为可观察的验收条件；不得用“效果更好”代替量化或行为标准。
4. 判断是运行时功能包、核心版本升级还是云端变更。运行时构造只接受第一类。
5. 记录需要的权限。权限不能从实现细节反推，必须先声明后使用。
6. 删除功能默认解释为隐藏/停用贡献；永久删除用户数据需要单独确认。

完成条件：目标、非目标、受影响页面、数据契约、权限、测试和回滚方式全部明确。
